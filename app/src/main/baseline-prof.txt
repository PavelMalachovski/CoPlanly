# CoPlanly's baseline profile (release audit, week 8): the code a cold start and the first
# screens run, compiled ahead of time on install instead of interpreted on first use.
#
# Written by hand, not recorded: recording one takes a Macrobenchmark module and a device run per
# release, and this repository's sessions have no Android SDK. The rules are package-level
# wildcards over the start path — the application, the activity, navigation, the theme, the shared
# components, the four tabs and their view models, and the Room layer they read — so a renamed
# class stays covered. AndroidX and Compose ship their own profiles inside their libraries; this
# file only adds the app's code. `tools/check-baseline-profile.sh` (the release CI job) fails when
# these rules stop reaching the release build.
#
