# CoPlanly — full audit, 30 September 2026

Five parallel reviews of `main` @ `dff636a` (PR #122 merged): the data and domain layer, the
presentation layer, the backend (functions, rules, web), the build/CI/dependencies/docs, and the
product and go-to-market plan. Every finding below was checked against the code. The fixes are in
PR #123; this file records what was found, what was fixed, and what is left and why.

## 1. Verdict

The codebase is in good shape for a closed test **once PR #123 is merged and deployed**. The audit
found two security holes in `firestore.rules` and three defects that corrupted or leaked shared
calendar data; all five are fixed with tests. Nothing found requires a schema change.

## 2. Fixed in PR #123

### Security and privacy (server)

| # | Finding | Fix | Proof |
|---|---|---|---|
| S-1 | A user could delete and re-create `users/{me}` with `partnerIds: [victim]` and pass `isMyAudience`, planting documents in the victim's sync | Create refuses partner fields and `role`; profile delete is admin-only | `users-profile.test.js`, incl. the end-to-end attack |
| S-2 | A former co-parent could create the conversation of a new pair under its id and read it | Conversation id must be `canonicalPairId(participants)` | `conversations` rules tests |
| S-3 | After unpair the ex-partner kept reading and editing the family's expenses and budgets | `isLiveFamilyMember` (the family document exists) | rules tests with the app's own query |
| S-4 | Unpair left calendar-friend grants of the ended family | Deleted with the professional grants | `unpair-callable.test.js` |
| S-5 | A friend invitation naming a dead family fell back to another family | Refused (`inviter-not-paired`) | functions tests |
| S-6 | Legacy `onEventCreated`/`onChildInfoUpdated` pushed English text with an e-mail, duplicated typed pushes, flooded on school imports | Both deleted; typed pushes remain | e2e test rewritten for the sync path |
| S-7 | Account deletion left the departed parent's answers in former families' parenting plans; accepted invitations kept `toEmail`; child `guests` kept the departed guest | Erased | functions tests |
| S-8 | A co-parent could change `familyId`/`isPrivate` of the creator's event | Pinned (blank `familyId` may be filled with the pair's own) | rules tests |

| S-10 | Calendar feed served from cache after an unpair | Liveness checked first | functions test |

### Build and CI

- Cloud Functions on **Node 22** (nodejs20 is being retired; the europe-west3 move creates every
  function). `npm audit fix`: 21 production advisories (3 critical) down to 8 moderate, all in the
  `firebase-admin` → `google-gax` chain.
- New release-job check that every 64-bit `.so` is 16 KB-page aligned (Play requirement).
- `release.yml` builds a signed APK beside the AAB; the dispatch note no longer reaches the script
  unquoted.
- Screenshot tests pin today's date (`LocalFixedToday`); they had depended on the weekday they ran.
- The functions suite no longer depends on today's date; its glob is quoted.
- Screenshots and Regenerate on pinned `ubuntu-24.04`; Regenerate rebases before pushing and no
  longer runs when its own workflow file is edited; `main` runs are never cancelled.
- CI path gates: `utils/` runs the screenshots, `data/security/` runs all three emulators.

## 4. Deploy order after merging PR #123

1. `backfillFamilyDocuments` — the new expense/budget rule needs `families/{id}` for every pair.
2. `firebase deploy --only functions` (Node 22, europe-west3).
3. `firebase functions:delete onEventCreated onChildInfoUpdated --region europe-west3 --force`
   (and `--region us-central1` if the old region still has them).
4. `firebase deploy --only firestore:rules,firestore:indexes`, then `--only storage`.

## 5. Product and go-to-market (summary)

- **Positioning:** "Jeden kalendář pro dvě domácnosti — čí je který den, co se mění a kolik to
  stálo." Beat "WhatsApp + a shared Google Calendar", not OurFamilyWizard; the Czech competitor
  that matters is app2us (149 CZK, no free tier).
- **Channels, in order:** family mediators (justice.cz register) with free professional access and
  a QR one-pager; Poradny pro rodinu; OSPOD pilots; Cochem-practice courts; family lawyers; parent
  portals and Facebook groups with identical neutral messaging to both camps. Austria before
  Germany (mandatory pre-divorce counselling), and Germany outside Bavaria.
- **Pricing:** one subscription per family, the second parent free, the calendar, custody, chat and
  expenses free for ever; documentation (export, verification) paid. First 12 weeks free.
- **Metric:** weekly active paired families (both parents active). Activation ≥ 40 % paired in 7
  days; D30 family retention ≥ 35 %.
- **Before testers:** the listing draft in `LAUNCH-PLAYBOOK.md` §3.3 still advertises budgets and
  omits export, plan, contact afternoons and the iPhone feed; buy a domain (also needed for OAuth
  verification); trademark search on the name; a support mailbox with a named reader.
