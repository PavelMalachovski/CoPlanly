# CoPlanly — Release, Motion and UI/UX Audit (September 2026)

Audit date: 2026-09-23. Baseline: `main` @ `5e3bbc1`. Fixes are on
`claude/charming-ritchie-d6uqz8`.
Scope: readiness for a **Google Play closed test**, motion consistency across screens, UI/UX of
every screen. Security, product strategy and the monetisation plan are out of scope; they are
covered by `docs/AUDIT-2026-08.md` and `docs/ROADMAP.md`.

This audit adds to `AUDIT-2026-08.md` rather than replacing it. **[FIXED]** marks what this
session changed. Everything else is a recommendation, tagged with who can do it:
- **[cloud]**: code, no device needed
- **[device]**: needs a phone to judge
- **[owner]**: needs a decision or console access

**Verification constraints.** There was no Android SDK in the audit environment. The Kotlin
changes were reviewed but not compiled; CI on the pull request is the first build.
`node tools/check-invariants.js` passes (locales, format arguments, push types, Gson keep rules).

## 1. Verdict

**The app is not ready to upload yet, and what blocks it is almost entirely outside the code.**
Engineering found three release-breaking defects that no document tracked. All three are fixed
here:

1. **The in-app language picker would have broken on every Play install.** An AAB is split by
   language by default, and Play then installs only the device's languages. A Czech phone that
   picks Deutsch in Settings would stay in Czech. Sideloaded APKs and CI never show this.
   **[FIXED]**: `bundle { language { enableSplit = false } }`.
2. **`release.yml` could never have produced an uploadable bundle.** A step-level `if:` is
   evaluated before that step's own `env:` exists, so both restore steps were always skipped.
   The result would have been an unsigned AAB with no `google-services.json`, which crashes at
   launch in `FirebaseModule`. **[FIXED]**: the guards moved into the shell, a missing Firebase
   config now fails the run, and the summary says "signed" only when all four signing secrets
   are present.
3. **Every date picker except three was off by a day.** Material3's `DatePickerState` works in
   UTC-midnight millis, but the pickers converted through `ZoneId.systemDefault()`. In Central
   Europe that highlighted the previous day. West of Greenwich it saved the previous day.
   Affected pickers: the event form (start date, recurrence end), change requests, and the shared
   child/pet picker (dates of birth, vaccinations). **[FIXED]**

What is left before the first upload is REL-1 through REL-7, which are consoles, a keystore, a
deploy, hosting and a lawyer. §2 lists what this audit adds to them.

## 3. Motion

### 3.1 What was wrong

There was no motion system: three duration vocabularies, and nothing read
`MaterialTheme.motionScheme`.
- `utils/AnimationConstants` used 150/300/500.
- `theme/Constants.AnimationConstants` used 150/200/300/2000 and had no callers.
- `MONTH_PAGING_MS` was 500.

The values actually in use were 150, 200, 300, 450, 500, 700, 900, 1200 and 2000, plus
unspecified springs. Specifically:

- **Friends, FriendDetail and FriendProfile** named no transitions, so they fell back to
  Navigation's own **700 ms** crossfade: 2.3× every other screen.
- **Tabs pushed.** Switching Home → Calendar slid in from the right like opening a detail
  screen, although tabs are peers with no direction.
- The **calendar view-mode crossfade** ran 150 ms below API 28 and 200 ms above.
- **Day/Week `AnimatedContent`** carried about 60 lines of slide spec with a direction fixed at 0.
  Only its 150 ms fade ever ran.
- **Auth** had no pop transitions.
- **The shimmer** used an eased curve, so the sweep sped up and slowed down.
- Dead code included two constant objects, `LoadingSkeleton.kt` (a second shimmer spec), five
  unused skeletons and six unused helpers.

### 3.2 Fixed

- `presentation/theme/Motion.kt`: `SHORT_MS` 150, `MEDIUM_MS` 300, `LONG_MS` 500. The navigation
  helpers, month paging (`MONTH_PAGING_MS` is now an alias), the view-mode crossfade, Day/Week and
  the splash exit read it. CLAUDE.md design item 11.
- The `NavHost` default is the standard push, so no route can fall back to 700 ms. Auth has pop
  transitions.
- **Tabs fade-through** (90 ms out, then 210 ms in with a 0.92 scale; 300 ms total). Arriving at
  a tab from a detail screen, or returning to one, still slides.
- The Day/Week fade is kept and the inert slide removed. The shimmer is linear. The dead code is
  deleted.

### 3.3 Still inconsistent: all [device], because each changes how something feels

1. **Expand/collapse uses three anatomies.**
   - Settings: fade + expand.
   - Child/medical editors: expand only (`AllergyEditor`, `ActivityEditor`,
     `EmergencyContactEditor`, `MedicationEditor`, `VaccinationListEditor`,
     `MedicalProfileEditor`).
   - Custody setup and Auth: fade + *slide* with no expand, so the layout jumps
     (`CustodySetupScreen.kt:298-315`, `AuthScreen.kt:260-303`).

   Recommendation: one `sectionEnter/Exit` pair (fade + expandVertically on
   `motionScheme.defaultSpatialSpec()`) added to `Motion.kt`.
2. **The calendar moves four ways.**
   - Month swipe settles on the 500 ms tween.
   - Day/Week swipe settles on the pager's spring.
   - The Month "Today" jump uses the library spring (`MonthView.kt:211`).
   - A Day/Week external jump is instant (`DayWeekView.kt:160`).

   Recommendation: pass `snapAnimationSpec = monthPagingTween()` to the Day/Week fling behaviour,
   and settle the Month jump with `animateScrollBy` over the offset, as `settleToNearestMonth`
   does.
3. **The Settings disclosure chevron swaps instantly** while its row animates
   (`SettingsScreen.kt` `DisclosureChevron`). Rotate it with `fastSpatialSpec()`.
4. **`CalendarBanners` has no enter/exit.** A change-request banner shoves the grid down in one
   frame.
5. **Form screens scale in from 0.8** while the screen underneath slides out. Either keep the
   scale at about 0.92 with a matching fade on the outgoing screen, or use the standard push.
6. **Bottom sheets are split.**
   - Plan, Guest and Budget skip the partial state.
   - The other seven do not, including EventPreview, DaySwap, MessageTemplates, FriendInvite,
     CalendarFilters and the chat sheet.

   Recommendation: `skipPartiallyExpanded = true` for short action sheets.
7. **The only bouncy spring in the app** is the parent card in `AddEditEventScreen.kt:805`.
   Switch it to `fastSpatialSpec()` unless `MotionScheme.expressive()` is adopted globally.
8. **Reduced motion.** Compose tweens follow the system animator scale, but the splash's
   `delay(700)` hold and the infinite pulses (splash, Auth logo) do not. Read
   `ANIMATOR_DURATION_SCALE` once in `Motion.kt` and drop the decorative pulses when it is 0. Also
   run the splash's text alpha and offset in parallel; they are sequential today, which makes
   about 2.25 s on every cold start.

## 5. Device checklist for the owner

One pass on a phone, in this order, covers everything this audit could not see:

1. Install the **AAB** from the release workflow through internal sharing, not an APK.
   - In Settings → Language, switch to a language the phone is *not* set to. (Tests §1.1.)
2. In dark theme and light theme, open each tab and look at the gap above the top bar and above
   the bottom bar. (Tests §4.2 insets.)
3. Open the chat and type. Does the keyboard cover the composer? Do the same in the event and
   expense forms.
4. Pick a date of birth and an event date. Does the picker open on the stored day, and is that
   day what gets saved? (Tests §1.3.)
5. Switch tabs and open a detail screen. Do the fade-through and the push both read as intended?
   (Tests §3.2.)
6. Tap an event on Home. Does the preview open, and does Edit work from it?
7. With TalkBack on, delete an expense via the actions menu and toggle "Private" on an event.
8. Everything REL-7 already asks, plus a Google Calendar import. (R8 and the `@Key` models.)
